# Tests

Run from the repository root:

```bash
python -m pytest analysis/tests -q
```

This is the fast CPU suite (synthetic data, no GSD or GPU). The real mixture
fixture is deliberately excluded from the default run.

## Real GSD integration regression

Inputs: `examples/mixture/eatt2/params.json` and `trajectory_0.gsd`.
Recorded baseline: `example_results/mixture/replicates.csv` and
`summary.csv`.

```bash
python -m pip install -r analysis/requirements-trajectory.txt
python -m pytest analysis/tests/test_integration_mixture.py -m integration -q
```

The test creates a temporary sweep/run layout, executes the complete
GSD -> pairing -> graph -> SQLite -> CSV pipeline, and compares **every**
column in both exported tables against the committed baseline. It also
checks independent composition and contact-conservation identities.

The reference CSVs were previously generated by the pipeline: they are a
regression baseline, **not independent proof of scientific correctness**.
Numerical tolerances permit small floating-point differences. The existing
hand-verifiable synthetic tests cover the scientific formulas separately.
Rebaseline only after investigating and independently validating changes.

This short mixture fixture is not production data. Generated NPZ/SQLite
artifacts stay in pytest's temporary directory and are not committed.

The original example is a flat directory, not a sweep containing a run
subdirectory. The test copies the two input files to a temporary
`<sweep>/eatt2/` layout before invoking the CLI.

This slower integration test is currently opt-in, not yet enabled in
GitHub Actions. Run it in the working cluster environment first.
